# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

## Презентер

Презентер реализован в виде набора обработчиков событий непосредственно в файле `src/main.ts`, без выделения в отдельный класс. Такой подход выбран потому, что приложение состоит из одной страницы и содержит единственный граф зависимостей — нет оснований добавлять уровень косвенности ради уровня косвенности.

### Принципы работы Презентера

- **Презентер только обрабатывает события, но никогда не генерирует их.** Все `events.emit()` вызываются либо внутри классов View (в ответ на действие пользователя), либо внутри классов Model (при изменении данных). Единственное исключение — callback-обработчики, которые Презентер передаёт в конструкторы View-компонентов: согласно архитектурным правилам, такие обработчики должны использовать брокер событий, поэтому они содержат `events.emit()`, но вызываются уже самим View-компонентом.

- **Перерисовка View происходит строго в двух случаях:**
  1. В обработчике события Модели — `catalog:changed`, `preview:changed`, `cart:changed`, `buyer:changed`.
  2. В обработчике события открытия модального окна — `basket:open`, `basket:checkout`, `order:submit`.

- **Презентер не хранит бизнес-данные.** Единственная переменная состояния — `currentPreview`, хранящая ссылку на текущий открытый компонент предпросмотра карточки. Она нужна для обновления кнопки «В корзину/Убрать», когда состав корзины меняется в то время, пока модальное окно с предпросмотром открыто.

### Обработчики событий Моделей

| Событие | Действие Презентера |
|---|---|
| `catalog:changed` | Создаёт карточки `CardCatalog` для каждого товара, передаёт массив в `Page.render()` |
| `preview:changed` | Если выбран товар — создаёт `CardPreview`, открывает модальное окно; если `null` — закрывает модальное окно, снимает блокировку страницы |
| `cart:changed` | Обновляет счётчик корзины в шапке; перерисовывает строки корзины; обновляет кнопку `inCart` в предпросмотре, если он открыт |
| `buyer:changed` | Передаёт данные покупателя и ошибки валидации в `OrderForm.render()` и `ContactsForm.render()` |

### Обработчики событий Представления

| Событие | Действие Презентера |
|---|---|
| `basket:open` | Рендерит актуальные строки корзины, помещает корзину в модальное окно, открывает его |
| `modal:close` | Сбрасывает `currentPreview`, снимает блокировку прокрутки страницы |
| `card:select` | Вызывает `catalogModel.setSelectedProduct()` — что порождает `preview:changed` |
| `cart:add` | Добавляет товар в модель корзины; сбрасывает выбранный товар через `setSelectedProduct(null)` — что закрывает модальное окно через `preview:changed` |
| `cart:remove` | Удаляет товар из модели корзины — `cart:changed` обновляет UI |
| `basket:checkout` | Очищает данные покупателя; помещает форму заказа в модальное окно |
| `order:change` | Передаёт изменившееся поле в `buyerModel.setData()` — `buyer:changed` обновляет форму |
| `order:submit` | Помещает форму контактов в модальное окно |
| `contacts:change` | Передаёт изменившееся поле в `buyerModel.setData()` — `buyer:changed` обновляет форму |
| `contacts:submit` | Отправляет заказ на сервер; при успехе показывает экран успеха, очищает корзину и данные покупателя |
| `success:close` | Закрывает модальное окно, снимает блокировку страницы |

### Базовый код

Все поля базовых классов являются приватными. Доступ к данным осуществляется через публичные методы и конструкторы.

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - приватное поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - приватное поле с базовым адресом сервера  
`options: RequestInit` - приватное поле с объектом заголовков для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - приватное поле, хранящее коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В приложении используются две основные сущности данных: товар и покупатель. Все данные описаны через интерфейсы, чтобы обеспечить единый контракт между слоями приложения.

`interface IProduct`
- `id: string` — уникальный идентификатор товара.
- `description: string` — текстовое описание товара.
- `image: string` — путь или URL к изображению товара.
- `title: string` — название товара.
- `category: string` — категория товара.
- `price: number | null` — стоимость товара. Может быть `null`, если цена временно отсутствует.

Назначение `IProduct` — описать структуру данных товара, которые хранятся в каталоге и могут добавляться в корзину.

`type TPayment = 'card' | 'cash'`
- вариант оплаты, который выбирает пользователь.

`interface IBuyer`
- `payment: TPayment | ''` — способ оплаты.
- `email: string` — почтовый адрес покупателя.
- `phone: string` — телефон покупателя.
- `address: string` — адрес доставки.

`type IBuyerErrors = Partial<Record<keyof IBuyer, string>>`
- тип для ошибок валидации данных покупателя.

## Модели данных

Все поля классов моделей являются приватными. Доступ к данным осуществляется исключительно через публичные методы классов (геттеры, сеттеры и другие методы).

В проекте реализованы три модели данных, каждая со своей зоной ответственности:
- модель каталога товаров;
- модель корзины;
- модель информации о покупателе.

### Модель каталога товаров

Отвечает за хранение списка всех товаров, доступных для покупки, и за выбор товара для подробного просмотра.

Конструктор:
- `constructor()` — модель не принимает параметры при создании. Изначально в модели пустой список товаров и нет выбранного товара.

Поля класса:
- `products: IProduct[]` — приватное поле с массивом всех товаров каталога.
- `selectedProduct: IProduct | null` — приватное поле с товаром, выбранным для подробного отображения.

Методы класса:
- `setProducts(products: IProduct[]): void` — сохраняет массив товаров, переданный в параметре, в модель.
- `getProducts(): IProduct[]` — возвращает текущий массив товаров из модели.
- `getProductById(id: string): IProduct | undefined` — возвращает товар по его идентификатору или `undefined`, если товар не найден.
- `setSelectedProduct(product: IProduct | null): void` — сохраняет товар для подробного отображения.
- `getSelectedProduct(): IProduct | null` — возвращает товар, выбранный для подробного просмотра.

### Модель корзины

Отвечает за хранение и изменение списка товаров, которые пользователь добавил в корзину.

Конструктор:
- `constructor()` — создаёт пустую корзину без товаров.

Поля класса:
- `items: IProduct[]` — приватное поле с массивом товаров, добавленных пользователем в корзину.

Методы класса:
- `getItems(): IProduct[]` — возвращает текущий массив товаров в корзине.
- `addItem(product: IProduct): void` — добавляет товар, переданный в параметре, в корзину.
- `removeItem(product: IProduct): void` — удаляет из корзины товар, который соответствует переданному объекту.
- `clear(): void` — очищает корзину от всех товаров.
- `getTotalPrice(): number` — возвращает общую стоимость всех товаров в корзине. Если стоимость товара отсутствует (`null`), такой товар учитывается как `0`.
- `getItemCount(): number` — возвращает количество товаров в корзине.
- `hasItem(id: string): boolean` — проверяет наличие товара в корзине по его идентификатору.

### Модель покупателя

Отвечает за хранение данных покупателя и валидацию введённых значений.

Конструктор:
- `constructor()` — создаёт пустую модель покупателя с начальными значениями полей.

Поля класса:
- `payment: TPayment | ''` — приватное поле с выбранным способом оплаты.
- `email: string` — приватное поле с email покупателя.
- `phone: string` — приватное поле с телефоном покупателя.
- `address: string` — приватное поле с адресом покупателя.

Методы класса:
- `setData(data: Partial<IBuyer>): void` — сохраняет одно или несколько полей покупателя без удаления остальных значений. Позволяет обновлять только адрес, телефон или email, не затрагивая остальной объект.
- `getData(): IBuyer` — возвращает полный объект данных покупателя.
- `clear(): void` — очищает все данные покупателя.
- `validate(): IBuyerErrors` — проверяет каждое поле модели. Возвращает объект с сообщениями об ошибках для тех полей, которые не прошли проверку. Если поле валидно, соответствующего свойства в возвращаемом объекте нет.

Зона ответственности модели покупателя — обеспечить безопасное хранение введённых данных и предоставить удобный механизм проверки валидности каждого поля до отправки заказа.

## Слой представления (View)

Классы View отвечают исключительно за отображение данных в интерфейсе. Каждый класс управляет одним блоком разметки. Компоненты не обращаются к моделям напрямую — в ответ на действие пользователя они генерируют событие, которое обрабатывает Презентер. Данные для отображения Презентер передаёт в метод `render`.

Все View-классы наследуются от базового `Component<T>`, где `T` — тип данных, которые можно передать через `render`.

### Типы данных View-слоя

### Класс Page

Управляет корневым блоком страницы: шапкой, счётчиком корзины и галереей товаров. Отвечает за блокировку прокрутки при открытом модальном окне.

Конструктор:
- `constructor(container: HTMLElement, events: IEvents)` — принимает корневой элемент страницы `.page__wrapper` и брокер событий.

Поля класса:
- `_counter: HTMLElement` — элемент счётчика корзины `.header__basket-counter`.
- `_catalog: HTMLElement` — контейнер галереи `.gallery`.
- `_basket: HTMLButtonElement` — кнопка корзины `.header__basket`.

Сеттеры (вызываются через `render`):
- `set counter(value: number)` — обновляет текст счётчика корзины.
- `set catalog(items: HTMLElement[])` — заменяет содержимое галереи переданными DOM-элементами.
- `set locked(value: boolean)` — добавляет или убирает CSS-класс блокировки прокрутки на `container`.

Генерируемые события:
- `basket:open` — клик по кнопке корзины. Данные: отсутствуют.

### Класс Modal

Управляет единственным модальным окном на странице `#modal-container`. Класс финальный — от него запрещено наследоваться. Любой контент, который нужно отобразить в модальном окне, передаётся снаружи в виде готового DOM-элемента.

Конструктор:
- `constructor(container: HTMLElement, events: IEvents)` — принимает элемент модального окна `#modal-container` и брокер событий.

Поля класса:
- `_content: HTMLElement` — контейнер содержимого `.modal__content`.
- `_closeButton: HTMLButtonElement` — кнопка закрытия `.modal__close`.

Методы класса:
- `open(): void` — добавляет CSS-класс активного состояния, делая модальное окно видимым.
- `close(): void` — убирает CSS-класс активного состояния и очищает `_content`.

Сеттеры (вызываются через `render`):
- `set content(value: HTMLElement)` — помещает переданный DOM-элемент в `_content`.

Генерируемые события:
- `modal:close` — клик по кнопке закрытия или по оверлею (фону) окна. Данные: отсутствуют.

### Класс Card (абстрактный, базовый для карточек)

Абстрактный родительский класс для всех трёх вариантов карточки товара. Содержит общие поля и методы работы с элементами, присутствующими во всех шаблонах карточек.

Конструктор:
- `constructor(container: HTMLElement, events: IEvents)` — принимает корневой DOM-элемент карточки (клонированный из темплейта) и брокер событий.

Поля класса:
- `_title: HTMLElement` — элемент `.card__title`.
- `_price: HTMLElement` — элемент `.card__price`.

## События приложения

Взаимодействие между слоями выстраивается через брокер событий `EventEmitter`. Классы View генерируют события в ответ на действия пользователя — непосредственно или через callback-обработчик, переданный в конструкторе. Презентер подписывается на события и обращается к Моделям и Представлениям для обновления состояния.

### События моделей данных

Генерируются моделью при изменении внутренних данных. Презентер подписывается на них и перерисовывает View.

| Событие | Источник | Данные | Описание |
|---|---|---|---|
| `catalog:changed` | `ProductCatalog` | — | Список товаров обновлён (`setProducts`) |
| `preview:changed` | `ProductCatalog` | — | Выбранный товар для просмотра изменился (`setSelectedProduct`) |
| `cart:changed` | `Cart` | — | Состав корзины изменился (`addItem`, `removeItem`, `clear`) |
| `buyer:changed` | `Buyer` | `IBuyerErrors` | Данные покупателя обновлены (`setData`, `clear`); вместе с событием передаётся объект с текущими ошибками валидации |

### События представления

Генерируются View в ответ на действие пользователя. Презентер вызывает методы моделей.

| Событие | Источник | Данные | Описание |
|---|---|---|---|
| `basket:open` | `Page` | — | Пользователь нажал на кнопку корзины в шапке |
| `modal:close` | `Modal` | — | Пользователь нажал кнопку закрытия или кликнул по оверлею модального окна |
| `card:select` | callback → `CardCatalog` | `{ id: string }` | Пользователь нажал на карточку товара в галерее |
| `cart:add` | callback → `CardPreview` | `{ id: string }` | Пользователь нажал «В корзину» в предпросмотре товара |
| `cart:remove` | callback → `CardPreview` / `CardBasket` | `{ id: string }` | Пользователь нажал «Убрать из корзины» в предпросмотре или кнопку удаления в корзине |
| `basket:checkout` | `Basket` | — | Пользователь нажал «Оформить» в корзине |
| `order:change` | `OrderForm` | `{ field: 'payment' \| 'address', value: string }` | Пользователь выбрал способ оплаты или изменил поле адреса |
| `order:submit` | `Form` (base) | — | Пользователь нажал «Далее» в форме заказа |
| `contacts:change` | `Form` (base) | `{ field: 'email' \| 'phone', value: string }` | Пользователь изменил поле email или телефона |
| `contacts:submit` | `Form` (base) | — | Пользователь нажал «Оплатить» в форме контактов |
| `success:close` | `OrderSuccess` | — | Пользователь нажал «За новыми покупками!» на экране успеха |

**Примечания:**
- События `cart:add` и `cart:remove` генерируются из callback-обработчиков, которые Презентер передаёт в конструктор `CardPreview` и `CardBasket`. Согласно правилам архитектуры, обработчик, переданный в класс представления, должен использовать брокер событий — этому требованию соответствует реализация в Презентере.
- Событие `order:change` генерируется как кнопками выбора оплаты (непосредственно в `OrderForm`), так и через базовый обработчик `input` из класса `Form` (для поля адреса). Оба пути используют одно имя события и одинаковую форму данных.
- `Form` при `submit` формирует событие из имени формы: `order:submit` для формы `name="order"`, `contacts:submit` для формы `name="contacts"`.

## Слой коммуникации

Для связи приложения с сервером используется отдельный коммуникационный слой. Он отвечает только за выполнение сетевых запросов и не содержит логики отображения.

Класс `CommunicationLayer` состоит из:
- конструктора `constructor(api: IApi)` — принимает объект, реализующий интерфейс `IApi`, и сохраняет его для дальнейшей работы;
- метода `fetchProducts(): Promise<IProductsResponse>` — выполняет GET запрос на эндпоинт `/product/` и возвращает объект сервера с массивом товаров;
- метода `sendOrder(order: IOrderRequest): Promise<IOrderResponse>` — выполняет POST запрос на эндпоинт `/order/`, отправляет данные покупателя и выбранных товаров, и возвращает объект подтверждения покупки.

Внутри `CommunicationLayer` используется композиция: класс не наследует `Api`, а принимает объект `IApi` в конструкторе и вызывает его методы `get` и `post`.

Типы данных для коммуникационного слоя описаны в `src/types/index.ts`. При этом:
- `IProductsResponse` использует существующий `IProduct` для массива товаров;
- `IOrderRequest` наследует все поля от `IBuyer` и дополняет их полями `total` (общая стоимость) и `items` (массив идентификаторов товаров);
- `IOrderResponse` описывает ответ сервера с подтверждением покупки.
